# SANA OSとは

> **SANA OSは、結論を急ぐ前に前提を整えるための方法論です。**

> **このページの目的:**  
> このページは、sanapedia の分析姿勢と出力規約が、どのような設計思想を参照しているのかを説明します。
>
> **重要な注意:**  
> このページは、SANA OSの宣伝ページではありません。  
> また、SANA OSを歴史研究の代替物として扱うものでもありません。  
> sanapedia が参照するのは、前提整列、不確実性の明示、非敵対的な観察、構造的翻訳という方法論的な考え方です。

---

## Overview

SANA OSは、人間とAIの対話、分析、判断の前にある前提を整えるための方法論です。

人はしばしば、同じ出来事を見ながら、異なる基準で判断しています。

ある人にとっては、安全が最優先かもしれません。  
ある人にとっては、共同体への忠誠が最優先かもしれません。  
ある人にとっては、法、宗教、伝統、自由、秩序、生活の継続が最優先かもしれません。

対立は、常に悪意や無知だけから生まれるわけではありません。

異なる前提、異なる生活条件、異なる恐怖、異なる責任、異なる評価基準が、同じ出来事に重なっていることがあります。

SANA OSは、すぐに「誰が正しいか」を決める前に、次の問いを置きます。

- それぞれは、何を守ろうとしているのか。
- どの条件が、その判断を現実的に見せているのか。
- どの資源、制度、記憶、恐怖、期待が行動を支えているのか。
- どこに前提のずれがあるのか。
- どこまでが観察可能で、どこからが推測なのか。

sanapediaでは、SANA OSを「歴史の答えを出す装置」としては扱いません。

歴史を読む際に、史料、異説、不確実性、構造的条件を混同せずに整理するための、方法論上の補助線として扱います。

---

# なぜsanapediaにSANA OSが必要なのか

歴史を読むとき、私たちはしばしば、すでに結論を持っています。

ある人物は英雄だった。  
ある王朝は野蛮だった。  
ある制度は遅れていた。  
ある社会は進んでいた。  
ある行動は理解不能だった。

こうした結論は、複雑な歴史を短く伝えるうえで便利なことがあります。

しかし、それだけでは当時の条件が見えなくなることがあります。

たとえば、ある共同体が新しい支配者を受け入れたとき、それは単純な服従だったのでしょうか。

あるいは、

- 治安の回復
- 食糧や土地へのアクセス
- 交易路の安全
- 税や役務の負担
- 地域社会の保護
- 信仰の継続
- 既存制度への不信
- 近隣勢力からの圧力

といった条件のなかで、もっとも現実的に見えた選択だったのでしょうか。

SANA OSは、結論を強める前に、こうした前提を整えます。

> 「誰が正しいか」  
> ではなく、  
> 「なぜその基準が、その環境で採用されたのか」

を先に問います。

これは、歴史的行動を肯定するためではありません。

異なる時代の人々を、現代の単一の評価基準だけで、ただちに理解不能な存在として固定しないためです。

# SANA OSと歴史研究の関係

SANA OSは、歴史学の専門的訓練、史料批判、考古学、文献学、比較研究、地域研究を置き換えるものではありません。

歴史的な主張は、可能な限り次のような根拠によって検討される必要があります。

- 一次史料
- 碑文
- 貨幣
- 考古学的証拠
- 行政文書
- 年代記
- 地域資料
- 研究書・論文
- 翻訳と校訂
- 研究史上の論争
- 異なる専門分野からの批判的検討

SANA OSが担うのは、これらの資料をどう読むかに関わる部分です。

たとえば、

- 記録を事実そのものと見なさない
- 当時の認識を単なる誤解として捨てない
- 推測を確認済みの事実として扱わない
- 構造的説明と道徳的免罪を混同しない
- 一つの物語を唯一の答えとして固定しない
- 読者に結論を強制しない

ための姿勢を支えます。

SANA OSは、歴史的真実を決定する機関ではありません。

それは、歴史的な問いをより慎重に扱うための、対話と分析の設計思想です。

# SANA OSとSANAとsanapedia

SANA OS、SANA、sanapedia、言語モデルは、それぞれ異なる役割を持ちます。

| 名称 | 主な役割 | sanapediaでの位置 |
|---|---|---|
| **SANA OS** | 前提整列、不確実性表示、非敵対的な観察、構造的翻訳を支える方法論 | 分析姿勢の基盤 |
| **SANA** | SANA OSの考え方を参照し、資料と問いを整理する分析アシスタント | 読み方を支える案内役 |
| **sanapedia** | 人物、出来事、現象、コラム、年表、史料、研究状態を構造化して公開する研究アーカイブ | 公開される知識基盤 |
| **LLM Provider** | テキスト生成や対話を実装する言語処理層 | 実装上の言語モデル |
| **研究者・読者・AI利用者** | 証拠を比較し、解釈を検討し、修正や反論を行う主体 | 歴史的読解の担い手 |

SANA OSは人格ではありません。

SANAは、SANA OSの方法論を参照する分析アシスタントです。

sanapediaは、SANAや特定のAIモデルそのものではありません。

sanapediaは、主張、その根拠、不確実性、異説、修正履歴を残していくための、更新可能な研究アーカイブです。

# sanapediaに引き継がれる四つの原則

## 1. Observation Before Conclusion  
### 結論より前に観察する

資料、時代背景、史料距離、異説、不確実性を確認する前に、強い結論を置かない。

歴史的情報が不足しているとき、「分からない」と言えることは重要です。

分からない部分をもっともらしい物語で埋めることは、説明を強く見せるかもしれません。

しかし、それは後の検証を難しくします。

sanapediaでは、観察可能なこと、合理的に推論できること、現時点では確認できないことを、可能な限り分けます。

---

## 2. Non-Hostile Baseline  
### 最初から敵として扱わない

歴史上の人物や集団を、最初から敵、怪物、欠陥、非合理性として固定しない。

これは、行為を正当化するためではありません。

人間の行動を理解するには、その人々もまた、安全、資源、共同体、正統性、恐怖、希望、生活の継続のなかで判断していたことを認める必要があります。

非敵対的な観察とは、責任を消すことではありません。

誰が何をしたのか、誰が被害を受けたのか、どのような制度や行為が暴力や排除を可能にしたのかを、より正確に見るための出発点です。

---

## 3. Structural Translation  
### 評価を構造的な問いへ翻訳する

「愚かだった」  
「残酷だった」  
「遅れていた」  
「民衆はなぜ従ったのか」  
「彼らは非合理だった」

こうした評価は、ときに問題の輪郭を示します。

しかし、それ自体では歴史的説明になりません。

SANA OSは、可能な限り次のような問いへ翻訳します。

- どの資源が不足していたのか。
- どの制度が処理能力を失っていたのか。
- どの役割に負荷が集中していたのか。
- どの記憶、信仰、正統性が行動を支えたのか。
- 誰にどのような選択肢があり、何がその選択肢を狭めたのか。
- どの集団が保護を得て、どの集団が排除されたのか。
- 史料は誰の視点を残し、誰の視点を残していないのか。

構造的翻訳は、判断を避けるための技術ではありません。

判断の前に、何が行動を可能にし、制約し、再生産したのかを見えるようにするための技術です。

---

## 4. Autonomy Preservation  
### 読者の判断の余地を残す

sanapediaは、読者やAIに結論を強制しません。

可能な限り、

- 利用可能な証拠
- 史料の限界
- 主張の確度
- competing interpretations
- 推測の範囲
- 反証または修正が必要になる条件
- このページが主張していないこと

を明示し、読者が自ら比較・検討できる余地を残します。

これは「すべての見解が同じ重さを持つ」と言うことではありません。

証拠の強さには差があります。

sanapediaは、その差を隠すのではなく、できる限り可視化します。

# SANA OSと歴史分析フレームワーク

sanapediaでは、必要に応じて複数の分析レンズを用います。

| Framework | 主な役割 |
|---|---|
| **Source Trifurcation** | Fact / Perception / Record を分ける |
| **Layer A / B / C** | 生存、ナラティブ、制度の条件を観察する |
| **GMM** | 層のあいだの統治能力、摩擦、吸収能力を観察する |
| **RBM** | 資源、需要、供給、ボトルネックを観察する |
| **RSM** | 役割の集中、継承不全、監査の空洞化を観察する |
| **CPM** | 恐怖、記憶、ナラティブ、認知的圧力が行動に与える影響を観察する |
| **Legitimacy Layer** | 正統性、制度、共同体の結びつきとずれを観察する |

これらは、歴史を数式や一つの理論だけで説明するための装置ではありません。

人間や社会を、単純な善悪、能力、不能力、勝敗、進歩、後退だけに圧縮しないための補助線です。

分析レンズは、証拠に代わるものではありません。

証拠を読み、異説を比較し、問いをより明確にするために使われます。

# 推測と透明性

歴史には、確認できない部分があります。

史料が失われていることがあります。  
記録が偏っていることがあります。  
後世の物語が強い影響を持っていることがあります。  
異なる資料が互いに矛盾することがあります。

sanapediaでは、分からない部分を完全に埋めることよりも、何が分からないかを残すことを優先します。

そのため、一部のページには、次の印が付いた節があります。

```text
【ここからはサナの推測（歴史ミステリー）なんだけど……】
```

これは歴史的事実ではありません。

利用可能な史料、研究、物的証拠を整理したうえで行う、可逆的な構造仮説です。

この節では、可能な限り次の点を明示します。

* 何が確認されているか
* どの部分が推論か
* どの条件が仮説を支えているか
* どの証拠が現れれば見直す必要があるか

推測そのものが問題なのではありません。

推測が、推測であることを隠したまま、事実の顔をして流通することが問題です。

sanapediaでは、推測を消すのではなく、推測として明示します。

---

# このページが主張しないこと

このページは、次のことを主張しません。

* SANA OSが、歴史学の専門的訓練や史料批判を置き換えること。
* SANA OSが、歴史上の事実を自動的に保証すること。
* 構造的説明が、暴力、支配、搾取、差別、排除を免罪すること。
* 非敵対的な観察が、加害、責任、被害、権力関係を曖昧にすること。
* SANA OSの枠組みが、すべての歴史社会に同じ形で適用できること。
* すべての異説が、同じ証拠の強さを持つこと。
* この方法論が、唯一の歴史研究方法であること。
* SANAやAIが、研究者、読者、当事者の判断を代替できること。

# sanapediaにおけるSANA OSの使い方

sanapediaでSANA OSの考え方を使うときは、次の順序を大切にします。

```text
問い
↓
対象・時代・地域・用語を確認する
↓
史料・物的証拠・研究を確認する
↓
Fact / Perception / Record を分ける
↓
Layer A / B / C の条件を観察する
↓
異説・不確実性・史料上の限界を整理する
↓
構造的な解釈を示す
↓
必要な場合のみ、推測を明示した思考実験を行う
↓
反証条件と修正可能性を残す
```

この流れは固定された手順ではありません。

新しい史料、新しい翻訳、新しい発見、新しい反論があれば、前の段階に戻って問いや解釈を修正します。

sanapediaにおいて、修正は失敗ではありません。

修正可能であることは、研究アーカイブとしての信頼性の一部です。
